# LMIT-2: Local Windows Wiki

LMIT-2 is the wiki-only knowledge-base layer for raw Markdown generated by
LMIT-1. It reads one or more local Markdown folders, imports them into a durable
knowledge-base layout, builds source notes, searches the wiki, and can ask
configured LLM providers to maintain topic/entity pages or answer grounded
questions.

LMIT-2 does not fetch URLs, log in to websites, run Playwright, convert
PDF/Office/image files, or reuse browser sessions. Those jobs belong to LMIT-1.

## Windows Local Deployment

The primary deployment target is now a local Windows install:

- PyInstaller builds `lmit-wiki.exe`.
- Inno Setup packages that executable into `LMIT-2-Wiki-Setup.exe`.
- The installer asks for a knowledge-base folder and the LMIT-1 `output/raw`
  source folder.
- The web UI binds to `127.0.0.1:8765` by default.
- The web UI runs `ingest`, `sync`, and `lint` from one place and shows the
  configured KB/source paths.
- Optional Windows scheduled tasks run `ingest`, `sync`, and `lint`.

Build the Windows package from the repository root:

```powershell
.\packaging\windows\build.ps1
```

If Inno Setup is not installed yet, build only the PyInstaller executable:

```powershell
.\packaging\windows\build.ps1 -SkipInstaller
```

The installer creates Start Menu entries for:

- `LMIT-2 Wiki Console`
- `LMIT-2 CLI Help`

See [docs/windows-local-install.md](docs/windows-local-install.md) for the full
local install flow and manual verification checklist.

## Long Filename Safety

LMIT-1 can produce useful but very long Markdown filenames, especially when
filename enrichment uses CJK titles. Linux filesystems often enforce a byte
limit per filename, so those names can fail when copied to NAS/Linux targets.

LMIT-2 avoids that failure mode during ingest. It keeps source traceability in
`manifest.json` and source-note metadata, but stores imported wiki files using
short ASCII names such as:

```text
knowledge_base/raw/<source-id>/<storage-key>-<slug>.md
knowledge_base/wiki/sources/source-<storage-key>.md
```

The manifest preserves:

- `original_source_path`
- `original_relative_path`
- `content_hash`
- `stored_raw_path`

Topic, entity, and query pages also use bounded slug/hash filenames so LLM-made
titles cannot create overlong files.

## Local Development

Install in editable mode:

```powershell
python -m pip install -e ".[dev]"
```

Initialize and ingest:

```powershell
lmit-wiki init --config config/wiki-only.windows.example.toml
lmit-wiki ingest --config config/wiki-only.windows.example.toml
lmit-wiki search --config config/wiki-only.windows.example.toml "openclaw"
```

Run the web UI:

```powershell
lmit-wiki serve --config config/wiki-only.windows.example.toml --host 127.0.0.1 --port 8765
```

Run tests:

```powershell
python -B -m pytest -p no:cacheprovider
```

The test suite provides its own `tmp_path` fixture because some Windows Python
versions create pytest temp folders with ACLs that are too restrictive in this
workspace. Set `LMIT_WIKI_TEST_TMPDIR` if you need those temp files somewhere
specific.

## LLM Providers

Supported providers:

- `ollama`
- `openai_compatible`
- `gemini`

Runtime settings live in `knowledge_base/.wiki_runtime.json`. The settings file
stores environment variable names such as `OPENAI_API_KEY` and `GEMINI_API_KEY`,
not API key values. Put actual keys in user or process environment variables.

LMIT-2 classifies source visibility during ingest:

- `public_web`
- `restricted_or_login`
- `local_private`

External cloud LLM providers are allowed only for public-only source sets. Local
or login-gated material is routed only to local/LAN providers such as Ollama or a
private OpenAI-compatible endpoint.
