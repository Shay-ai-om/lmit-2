# LMIT-2: LLM Wiki

LMIT-2 is the wiki-only knowledge-base layer for raw Markdown generated by
LMIT-1. It reads Markdown folders, copies them into a durable knowledge-base
layout, builds source notes, searches the wiki, and can ask configured LLM
providers to maintain topic/entity pages or answer grounded questions.

This repository intentionally does not fetch URLs, log in to websites, run
Playwright, convert PDFs/Office files/images, or reuse browser session cookies.
Those jobs belong to LMIT-1.

## Architecture

```text
raw Markdown folders
  -> source scanner
  -> raw copy / manifest
  -> source notes
  -> topic/entity/query pages
  -> index and append-only log
```

Default output layout:

```text
knowledge_base/
  raw/
  manifest.json
  .wiki_runtime.json
  .wiki_state.json
  schema/
  wiki/
    index.md
    log.md
    sources/
    topics/
    entities/
    queries/
```

## Install Locally

```powershell
python -m pip install -e ".[dev]"
```

Initialize and ingest:

```powershell
lmit-wiki init --config config/wiki-only.example.toml
lmit-wiki ingest --config config/wiki-only.example.toml
lmit-wiki search --config config/wiki-only.example.toml "openclaw"
```

Run the web UI:

```powershell
lmit-wiki serve --config config/wiki-only.example.toml --host 0.0.0.0 --port 8765
```

## Docker

Build and run:

```bash
docker compose -f docker-compose.example.yml up --build
```

Run scheduled jobs:

```bash
docker compose -f docker-compose.example.yml run --rm llm-wiki \
  lmit-wiki ingest --config /config/wiki-only.toml

docker compose -f docker-compose.example.yml run --rm llm-wiki \
  lmit-wiki sync --config /config/wiki-only.toml --limit 20

docker compose -f docker-compose.example.yml run --rm llm-wiki \
  lmit-wiki lint --config /config/wiki-only.toml
```

Mount raw Markdown as read-only volumes under `/data/raw/<stable-source-id>`.
Mount `/data/knowledge_base` as the writable wiki state volume.

## LLM Providers

Supported providers:

- `ollama`
- `openai_compatible`
- `gemini`

Runtime settings live in `knowledge_base/.wiki_runtime.json`. The settings file
stores environment variable names such as `OPENAI_API_KEY` and `GEMINI_API_KEY`,
not API key values. Put actual keys in container or host environment variables.

LMIT-2 classifies source visibility during ingest:

- `public_web`
- `restricted_or_login`
- `local_private`

External cloud LLM providers are allowed only for public-only source sets. Local
or login-gated material is routed only to local/LAN providers such as Ollama or a
private OpenAI-compatible endpoint.
